## 2025-03-12 - Fix PowerShell Command Injection Vulnerability
**Vulnerability:** Calling PowerShell via `ProcessStartInfo` allowed arbitrary command execution because user-supplied or dynamically-acquired input (`vmName` and `vhdxPath`) was directly interpolated into the command string without escaping single quotes, and the full command was passed as a single string to the `Arguments` property.
**Learning:** Even when the program itself starts `powershell.exe`, if the input parameters are passed as a single string to `Arguments` or interpolated directly into a PowerShell script without proper quoting/escaping, command injection is possible.
**Prevention:** Always use `ProcessStartInfo.ArgumentList` instead of a single `Arguments` string when passing parameters to an executable like PowerShell. Furthermore, when dynamic inputs are embedded into PowerShell script blocks within the `-Command` parameter, always sanitize them by properly escaping characters (e.g., doubling single quotes `''` for string literals) or use proper PowerShell argument binding when feasible.
