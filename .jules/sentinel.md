## 2025-03-09 - Fix PowerShell Command Injection using Environment Variables
**Vulnerability:** The application was vulnerable to PowerShell command injection because untrusted variables (like virtual machine names and disk paths from WMI or Hyper-V) were being directly interpolated into PowerShell script strings passed to `powershell.exe -Command`.
**Learning:** Bypassing command injection in PowerShell through manual string replacement (e.g. `vmName.Replace("'", "''")`) is fragile and doesn't handle all edge cases or block escaping of the interpolated context.
**Prevention:** Always use `ProcessStartInfo.EnvironmentVariables` to pass data safely as environment variables, and reference them in the PowerShell script as `$env:VARNAME`. Avoid string interpolation entirely for executing external processes with untrusted input.
