## 2026-03-13 - Fix command injection in PowerShell execution
**Vulnerability:** The application was vulnerable to command injection in `MainWindow.xaml.cs` via `RunPowerShellCommand`, where unsanitized user inputs (`vmName`, `vhdxPath`, and WMI `name`) were interpolated directly into PowerShell scripts, and the `ProcessStartInfo` passed the entire script as a single `Arguments` string. This could allow execution of arbitrary PowerShell code if an attacker provides malicious input (e.g. `'; malicious-command; #`).
**Learning:** Even internal tools that interact with local infrastructure (Hyper-V) via PowerShell are vulnerable to command injection if input is not sanitized or passed securely, especially when constructing complex PowerShell scripts as strings.
**Prevention:** Always use `ProcessStartInfo.ArgumentList` instead of concatenating strings for the command-line arguments to avoid shell injection when starting a process. Furthermore, sanitize any dynamic input embedded within PowerShell script strings by properly escaping quotes (e.g. replacing `'` with `''` in single-quoted strings).
