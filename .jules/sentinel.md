## 2025-03-17 - PowerShell Command and Script Injection
**Vulnerability:** The application was passing dynamic PowerShell commands to `powershell.exe` by constructing the `-Command` string using string interpolation. It was also embedding unsanitized user inputs (`vmName` and OS-retrieved `vhdxPath`) into these PowerShell scripts wrapped in single quotes (`'`). Both practices allowed for arbitrary PowerShell code injection if the strings contained `"` or `'`.
**Learning:** Using `Arguments = $"-Command \"{command}\""` for `ProcessStartInfo` is unsafe and susceptible to injection via double quotes. Embedding string variables inside PowerShell scripts surrounded by single quotes is also unsafe if the variables contain a single quote, which breaks out of the string context.
**Prevention:** Always use `ProcessStartInfo.ArgumentList` to securely pass command-line arguments to processes like `powershell.exe`. When dynamically embedding strings into a PowerShell script wrapped in single quotes, always escape the input by doubling single quotes (`input.Replace("'", "''")`).

## 2023-10-27 - WMI Query Injection
**Vulnerability:** The application was passing dynamic PowerShell commands to `powershell.exe` to query WMI. It was using a string interpolation like `Where-Object {{ $_.Name -like '*{name}*' }}`. If the `name` variable contained a single quote (`'`), it could result in PowerShell command injection, because the name retrieved via WMI (`Win32_VideoController`) could theoretically be spoofed or manipulated in some environments. Same for `vhdxPath`, `vmName` and other parameters used to build PowerShell scripts.
**Learning:** Variables obtained from WMI or other OS components must be treated as untrusted data, just like direct user input. It is never safe to dynamically build strings within double or single quotes for `-Command` execution of PowerShell without thorough escaping or better yet, using Environment Variables.
**Prevention:** Avoid string interpolation directly into PowerShell scripts wrapped in double/single quotes. Prefer passing arguments securely via `ProcessStartInfo.EnvironmentVariables` and reference them inside the script with `$env:VAR_NAME` which is natively evaluated by PowerShell safely.
