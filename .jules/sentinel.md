## 2024-06-05 - Fix PowerShell Command Injection via String Interpolation
**Vulnerability:** PowerShell scripts in `MainWindow.xaml.cs` were vulnerable to command injection because user-provided inputs (`vmName`, dynamically retrieved `vhdxPath`, and GPU name) were directly interpolated into PowerShell command strings and executed using `ProcessStartInfo`. Even though the code attempted to sanitize `vmName` and `vhdxPath` by replacing single quotes with two single quotes (`'\'\'`), this is insufficient. A properly crafted string could still bypass this rudimentary escaping or exploit the interpolation if the variables were placed in different contexts, leading to arbitrary command execution on the host machine with the privileges of the application.
**Learning:** Using string interpolation (`$"{variable}"`) to build shell commands is inherently insecure, even with basic escaping. C# applications that invoke external processes like `powershell.exe` must pass data securely.
**Prevention:** Never use string interpolation to pass variables to PowerShell or any other shell. Instead, use environment variables to pass the data, and reference those environment variables within the PowerShell command (`$env:VARIABLE_NAME`). This ensures that the data is treated as data by the shell, not as executable code. This pattern was established by adding an optional `IDictionary<string, string>? envVars` parameter to the `RunPowerShellCommand` helper method.
